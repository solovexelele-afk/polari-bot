# ❄️ POLARI — Discord-бот и система сервера

Python 3.11+ · discord.py 2.4+ · SQLite (aiosqlite) · slash-команды · persistent views.

## 2. Что умеет POLARI

| Система | Возможности |
|---|---|
| **/setup** | DRY RUN и APPLY с подтверждением. Ничего не удаляет и не переименовывает, не создаёт дубликатов (точные совпадения и алиасы используются, похожие названия помечаются «сомнительными» и не трогаются), права ставит только на новые объекты. Перед применением план пересчитывается; если сервер изменился, применение отменяется |
| **Вступление и обзвон** | Роль «На проверке» при входе, приветствие с баннером и кнопками «Правила» и «Комната ожидания», уведомление проверяющим при входе в комнату ожидания с кнопкой «Взять на собеседование» (перемещает в свободную комнату), `/interview_pass /fail /reset /status /queue`, атомарная смена ролей (одним запросом), история в БД, панель с очередью, историей и статистикой по проверяющим |
| **Памятка** | Select Menu: Персонал (живой список сотрудников), Команды, Роли, События, Магазин, Правила, Поддержка |
| **Правила** | Отдельный Embed на каждое правило (номер, название, описание, наказание, предупреждение), термины, меню поиска и листалка |
| **Магазин** | Карточки товаров, «Купить» открывает приватный тикет заказа (кастомные роли спрашивают название и цвет). Кнопки: Подтвердить оплату, Отклонить оплату, Отменить заказ, Добавить сотрудника, Закрыть тикет. Оплату подтверждает **только** сотрудник магазина (не сам покупатель), после этого роль выдаётся автоматически, а когда срок покупки истекает, снимается. Есть история заказов (`/orders`, «Мои заказы») и журнал операций `payments` |
| **Тикеты** | 7 типов, модальное окно, приватный канал, нумерация, лимит открытых тикетов и кулдаун, «Принять», «Добавить сотрудника», «Закрыть» с транскриптом (в лог, в ЛС автору, в `data/transcripts`) |
| **Модерация** | `/ban` (+ временный), `/unban`, `/kick`, `/mute`, `/unmute`, `/timeout`, `/untimeout`, `/warn` (3 варна → автобан на 30 дней), `/unwarn`, `/warnings`, `/clear`, `/slowmode`, `/lock`, `/unlock` (восстанавливает прежние права), `/report`. Проверяются иерархия ролей, уровень персонала и защита владельца. Лимит банов и киков за окно времени с тревогой в лог |
| **Логи** | Вход и выход, собеседования, роли (с автором из аудит-лога), тикеты с транскриптами, заказы и оплаты, наказания, автомод, удаление и изменение сообщений, каналы, роли сервера. Токены, пароли, номера карт и API-ключи маскируются |
| **Сообщество** | Приветствие и прощание, `/stats`, `/userinfo`, `/serverinfo`, `/rep give/show`, `/suggest` (+ ветка обсуждения, `/suggestion_status`), `/poll`, `/event` с кнопкой «Участвую», антифлуд, антиспам, антикапс, защита от масс-упоминаний (персонал не затрагивается) |
| **Админ-панель** | `/config show/set/link_role/link_channel`, `/panel` (переопубликовать), `/announce` |

### Уровни доступа

| Полномочие | Кто |
|---|---|
| Собеседования | 🎧 Проверяющий, Администратор и выше |
| Тикеты | 💬 Поддержка, Младший модератор и выше |
| Магазин (оплаты) | 🛒 Сотрудник магазина, Главный администратор и выше |
| Логи | Администратор и выше |
| /setup, /config | Владелец сервера, Administrator, Зам. основателя |
| warn/mute/timeout/clear · lock/slowmode · kick · ban | ур. 40 · 50 · 60 · 70 |

Administrator получает только роль «Основатель». Остальные роли получают минимально необходимые права.

## 3. План структуры (создаётся через /setup)

Роли (сверху вниз): 👑 Основатель, 💠 Зам. основателя, 🔷 Главный администратор, 🔹 Администратор, 🌀 Старший модератор, 🛡️ Модератор, 🔰 Младший модератор, 🎧 Проверяющий, 💬 Поддержка, 🛒 Сотрудник магазина, 🧊 Персонал, ✦ Кастом спонсор, 💎 Алмаз, 💠 Даймонд спонсор, ❄️ Спонсор, 🤝 Партнёр, ⭐ VIP, ✅ Прошёл обзвон, 🌊 Участник, ⏳ На проверке.

Категории:
- **💙 Знакомство:** все видят, писать нельзя. Каналы: новости, памятка, правила, магазин, профили.
- **🌸 Прихожая:** видят «На проверке» и персонал. Каналы: информация, новички, Ожидание 1–5, Собеседование 1–3. Зайти в комнаты собеседования новичок не может, его перемещает проверяющий.
- **💬 Общение:** только для участников. Каналы: чат, медиа, команды, предложения, голосования, мероприятия, 2 голосовых.
- **🎫 Поддержка:** каналы для панели тикетов.
- **📨 Тикеты:** приватная категория для тикетов.
- **🛡️ Персонал:** объявления, чат персонала, обзвон-панель, заказы (только магазин).
- **📜 Логи:** 8 каналов, видит только администрация.

Полный шаблон находится в `bot/data/blueprint.py`. Количество комнат задаётся в `.env`.

## 4. ⚠️ Нужно ваше утверждение

1. **Сроки наказаний в правилах** (`bot/data/content.py`, `RULES`): тексты правил TENDERLE опубликованы картинками, поэтому сроки предложены мной. С TENDERLE подтверждены только «3 варна → бан на месяц» и определение личной информации.
2. **Цены VIP (1000) и «Кастомной роли» (1500)**: на TENDERLE их не было.
3. **Цены спонсорских ролей** скопированы с TENDERLE. При необходимости измените их там же.

## 5. Запуск

1. В [Developer Portal](https://discord.com/developers/applications) откройте приложение, затем **Bot**:
   - нажмите **Reset Token** и скопируйте токен;
   - включите **Server Members Intent** и **Message Content Intent**.
2. **OAuth2 → URL Generator**: scopes `bot` и `applications.commands`. Права: Manage Roles, Manage Channels, Kick, Ban, Moderate Members, Manage Messages, Move Members, View Audit Log, Read/Send Messages, Embed Links, Attach Files, Add Reactions, Create Public Threads, Connect. Пригласите бота на сервер POLARI.
3. Установите зависимости и настройте окружение:
   ```powershell
   cd POLARI
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   copy .env.example .env      # впишите DISCORD_TOKEN и GUILD_ID
   python assets/generate_banner.py
   python main.py
   ```
4. В **Настройки сервера → Роли** перетащите роль бота **POLARI** выше всех ролей, которыми он управляет (кроме Основателя).
5. На сервере выполните `/setup mode:DRY RUN`, проверьте план, затем `/setup mode:APPLY` и нажмите **«Применить»**.
6. Сомнительные совпадения при необходимости привяжите вручную: `/config link_role` и `/config link_channel`.
7. Раздайте персоналу роли. Проверяющим нужна 🎧 Проверяющий, сотрудникам магазина 🛒 Сотрудник магазина.

Данные хранятся в `data/polari.db`, логи в `data/logs/polari.log`. Кнопки продолжают работать после перезапуска.

## 6. Хостинг на Render

В репозитории есть `render.yaml` (Blueprint). Он описывает Web Service на бесплатном плане:
- бот открывает health-check на `$PORT`;
- каждые 10 минут пингует сам себя, чтобы не уснуть;
- база данных бэкапится в Discord-канал.

1. Render → **New → Blueprint** → выберите этот репозиторий.
2. Заполните переменные:
   - `DISCORD_TOKEN` — токен бота;
   - `GUILD_ID` — ID сервера;
   - `BACKUP_CHANNEL_ID` — ID приватного канала для бэкапов, например `⚙️・сервер-лог` после `/setup` или отдельного канала, который видит только администрация.
3. **Apply.** Сборка займёт 2–3 минуты, затем бот появится в сети.

На бесплатном плане диск очищается при каждом деплое и перезапуске. Поэтому бот:
- сохраняет базу в канал бэкапов каждые 30 минут и при остановке;
- при старте восстанавливает базу из последнего бэкапа;
- по команде `/backup` делает бэкап вручную.

Пока `BACKUP_CHANNEL_ID` не задан, данные теряются при перезапуске. Надёжнее всего платный план с Persistent Disk: смонтируйте диск в `/opt/render/project/src/data`.
